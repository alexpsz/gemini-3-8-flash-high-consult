# Native operation and recovery

Read only for an existing native request or explicitly chosen native route. New interactive browser consultations use [browser workflow](browser-workflow.md); CLI execution uses [CLI](cli-workflow.md). Fallback is possible after established `NOT_SENT`; never switch an uncertain or submitted request to CLI/native and resend. Mac manual-assisted delivery has been observed; automatic model selection/input/send remain unverified.

## Reuse observations

Discover the current host's native capability and read its documentation once; restore documentation after context reset. Use observed app/window identities and fresh controls, not Windows imports or old coordinates on macOS. Do not recover this native conversation through CLI, hidden session databases, desktop CDP or browser-chat substitution.

One controller owns native UI across advisers. Each transaction is focus, fresh state, one action, verify; release ownership afterwards. File preparation, validation and independent model generation run concurrently. Do not hold the UI while a model thinks.

Cache selected model, effort, project, environment and conversation with observation time and source. Recheck affected facts when those contexts change or evidence conflicts; focus changes and unchanged polls do not require reopening pickers. Refresh controls after UI mutations. `Gemini 3.8 Flash` plus `High` must be visibly selected; the selected control and inspected picker must agree. Menu membership, Fast badges and model self-description are insufficient. Keep current verification through dispatch unless relevant state changes.

## Project and file access

Resolve the approved canonical root locally; record instructions, branch/HEAD or non-Git status and dirty state. Preserve existing files and project entries. An exact native root path verifies workspace binding; basename alone is a candidate. Record environment, additional roots and inherited context separately. A review relying on implicit workspace rules/context requires exact binding before dispatch.

An unregistered existing directory may be registered within authorized consultation scope. Judge `New Project` by its actual flow: existing-folder registration differs from creating directories, cloning or initializing repositories. Use visible descriptions/options and the approved root. Do not repeat permission already granted. A user's observation that matching names/paths merge is a case-specific clue, not a global guarantee. If automatic approval rejects the action, preserve its reason and use a supported, demonstrably safer route or obtain the required authorization; do not bypass through alternate input methods. One bounded path check suffices.

For explicit-file review in an existing candidate project, allow **file_access_corroboration** without claiming exact workspace binding. The packet contains a fresh marker absent from the wrapper. Require the exact approved packet as first native read; failure or missing marker stops substantive work in that conversation. Echo marker and a content fact, then continue within the exact allowlist. The controller compares them when observed, including after the first answer: this is retrospective content corroboration, not a controller-approved gate before analysis. Keep `ui_root_path` unverified and implicit context unknown. Never infer all inputs were read from one marker.

## One recovery, one handoff

Inspect the rendered wrapper, attachments and focus before controller send; compare complete text with the prepared file. Use `UNKNOWN` before the send action and `SENT` only after visible submission. A timeout may have acted: inspect, never blindly repeat.

After no visible effect or a native window error, refresh/reacquire once using supported APIs. Persist the failed operation, error, before/after state and recovery used. If the shared input capability remains broken, do not repeat this cycle separately for folder, model, menu and composer. Hand off all remaining manual steps together: exact existing root, target model/effort, exact wrapper file and one send. Persist `UNKNOWN` before this handoff. Recover by request ID, conversation locator and visible submitted turn; user confirmation alone is insufficient. Mark truncated submitted text as fidelity unverified, and recover the same turn once; never resend for a missing suffix. Manual success does not prove automation repaired.

Login/security controls, unsupported helpers, locked desktop, actual access prompts and user stops follow current host rules. Do not change permission presets or use terminal panes. Stop native input on a user stop until authorized to resume. Stop unauthorized commands/product edits through a visible control; inspect differences read-only without reverting user changes.

## Wait without repeated setup

Poll only named completion outputs after 30 seconds, backing off to 60 while unchanged. About every 60 seconds, acquire UI ownership for a bounded same-conversation health check, including approval/error states even when completion is absent. Prefer AX; full screenshots only resolve missing or conflicting evidence. Do not reopen model/project controls routinely. Keep unchanged state silent; report meaningful progress, blockers or requested status. Follow any host requirement for more frequent user updates.

At completion, record AX and screenshot timestamps separately. If AX says stopped while pixels show Working/Stop, mark conflict and refresh the same conversation once; do not certify agreement or restart the request. Remaining conflict is an explicit limitation.
