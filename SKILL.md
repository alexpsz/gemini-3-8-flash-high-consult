# Gemini 3.8 Flash High consultation

Obtain one original assessment; the controller verifies claims and owns subsequent decisions. An explicit consultation request authorizes sharing necessary evidence and writing named outputs. Reuse that authorization; automatic skill selection alone does not authorize disclosure or product changes.

For interactive consultations, prefer the signed-in official Antigravity browser client connected to the intended local machine/project. Use CLI for explicit CLI requests, background concurrency, precise parameter control or automated raw-output collection. Preserve the normal harness, skills, rules and configured tools on either route; browser availability alone does not establish local execution or matching skills/plugins. Target `gemini-3.8-flash-high` and effort `high`; report selected configuration separately from observed effective model/effort.

Relevant public web search and page reading are normal consultation capabilities; the user need not request them separately each time. Use them when useful and cite sources actually accessed. Explicit offline instructions, narrower scope and existing deny/ask or managed rules take precedence. Read [CLI workflow](references/cli-workflow.md) for the authorized `read_url(*)` profile setup; it does not remove all permission friction from the harness.

1. **Resume first.** Reuse the request, packet, manifest and conversation. Keep `UNKNOWN` or `SENT` on its original route; never resend or switch transports to repair a timeout or collection failure. Reuse verification until its relevant context changes.
2. **Prepare independently.** For new evidence, read [packet preparation](references/context-packet-template.md). Keep prior verdicts outside the first request; scan and inspect outgoing material. Prepare other advisers concurrently and dispatch each ready route without waiting for blocked routes.
3. **Choose the route.** Read [browser workflow](references/browser-workflow.md) for interactive browser consultations or [CLI workflow](references/cli-workflow.md) for CLI execution. Use [native workflow](references/native-workflow.md) for desktop operation and recovery. A replacement route requires established `NOT_SENT`; one UI owner serializes UI actions. Never assume `--mode plan` enforces read-only access.
4. **Collect once.** Read [delivery](references/delivery-protocol.md). Persist `UNKNOWN` before launch/send and `SENT` only with submission evidence. Preserve the complete first answer and native transport records. A runner receipt is controller evidence, not an adviser-authored completion file; delivery success does not validate model identity or factual claims.
For CLI dispatch or continuation, read [runtime checks and recovery](references/runtime-recovery.md). Every runner launch checks default web policy and declared input hashes; prepare Gemini evidence inside the owning project or reuse exact existing read grants. Reuse matching local setup observations, use one visible terminal for required login, and classify host, authentication, model and tool-permission failures separately. Use the bundled `--continue-from` only for an authorized new follow-up, preserving web defaults and the recorded native session. Watch live receipt phases; collect access evidence offline after completion.


Report observed model/effort, project versus file-access evidence, manual involvement, transport/collection status, access limitations and locally supported findings. Apply changes only within the user's authorized scope.

For the first CLI dispatch on Windows, follow [Windows CLI setup](references/windows-setup.md). Generate a machine-local profile; never reuse a macOS profile or another user’s credentials.
